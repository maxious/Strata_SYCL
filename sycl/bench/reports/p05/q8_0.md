# P0 #5 — Q8_0 pre-unpack feasibility

Sources transcribed: `include/strata/artifact/dequant.hpp` and
`sycl/src/kernels/cuda/native_mmvq.dp.cpp`. Line citations are against those files as they
stand at the time of writing. No code was changed; this is a read-only feasibility report.
Per-tensor usage accounting is intentionally out of scope (a separate usage node owns it).

## 1. Confirmed: Q8_0 blocks are already raw signed bytes — there is no unpack to pre-unpack

The on-disk/wire `Q8_0` layout is one `fp16` block scale `d` followed by 32 raw `int8`
quants, with no bit-packing:

* scalar reference, `dequant.hpp:80-87` —
  `dequantize_q8_0` reads `d = fp16_to_fp32(read_u16(block))`, treats the rest as
  `(const int8_t*)(block + 2)` and linearly maps `out[j] = (float)qs[j] * d`. Reading 32
  bytes straight out of the block; there is no nibble/bit gather.
* block struct, `native_mmvq.dp.cpp:104-106` — `struct Q80Block { sycl::half d; int8_t qs[32]; };`,
  and its layout is pinned by `static_assert(sizeof(Q80Block) == 34 && alignof(Q80Block) == 2
  && offsetof(Q80Block, qs) == 2)` (`native_mmvq.dp.cpp:130`).

The native Q8_0 decode already consumes those bytes with a **no-bit-unpack load + dp4a**
path. The narrow (`small`) dot reads each 16-quant quarter as plain ints and runs
`dp4a` with zero unpacking:

* `native_mmvq.dp.cpp:807-816` — `small_q8_dot(const Q80Block* w, ...)`:
  `v = load_int_b2(w->qs, iqs+i)`, `u = *(int*)x->qs`, `sumi = STRATA_DP4A(v, u, sumi)`,
  then `return d0 * d1 * sumi`.

And the wide dispatch routes Q8_0 through `Wide32Q8`, which is the same raw-bytes
load+dp4a kernel:

* `native_mmvq.dp.cpp:2719-2722` — `native_q8_0_mmvq` first tries `try_wide32<Wide32Q8>`,
  falling back to `small_mmvq<Q80Block, 8>`.
* `native_mmvq.dp.cpp:1720-1733` — `struct Wide32Q8 { using Block = Q80Block; LPB = 2; ... }`;
  `load` reads `load16_a2(b->qs + 16*l)` (raw 16-quant halves) and `apply` is
  `r.d * xb->ds[0] * dp4a4(r.q, ld_q8_16(xb, r.half), 0)` — again no bit unpack in the
  decode.

Because the payload is already one `int8` per element, the per-token cost that motivated the
Q6_K pre-unpack — the in-kernel 6-bit unpack/gather that sat on the ALU int pipe — simply does
not exist for Q8_0. Pre-unpacking would at best copy bytes into a nominally identical signed-
byte block; it would add a one-time pass and a second buffer while producing no decode-time
savings.

`native_mmvq.dp.cpp:2501-2502` makes the relationship explicit: the Q6_K pre-unpack exists
precisely to land on "the identical load+dp4a path the Q8_0 wide32 kernel uses (Wide32Q6U
mirrors Wide32Q8 …), so the decode land[s] at the measured ~2x ceiling." That is, **Q8_0's
Wide32Q8 kernel is the ceiling proxy the Q6_K work was aiming at** — the target, not a
candidate for further unpacking. This matches the context that `q6k_preunpack_bench` used the
Q8_0 path as the ~2x ceiling reference.

## 2. The only known open piece: llama.cpp wide-load/ESIMD DMMV reorder

The only identified avenue that could still move the Q8_0 decode is the llama.cpp wide-load /
ESIMD DMMV permutation/reorder. Per the task context (sourced from `README.sycl.md` and
`docs/sycl-experiments/12`), exp 12 measured this reorder as **not a win on Q8_0**, so it is
not currently pursued. It is the sole exception to "no unpack to do"; nothing else is open on
this encoding.

## 3. Concrete: Q80Block fields and per-subblock ops

Fields (`native_mmvq.dp.cpp:104-106`, layout pinned at `:130`; scalar contract at
`dequant.hpp:80-87`):

* `sycl::half d` — one fp16 scale at offset 0; applies to the whole 32-element block.
  (Contrast Q6_K's unpacked `Q6UBlock { float d0, d1; int8 qs[32]; }`, which carries **two
  per-16 scales**; Q8_0 has **no per-16 scale** — a single `d` covers all 32 quants.)
* `int8_t qs[32]` — 32 signed-byte quants at offset 2, no bit-packing, read as-is.

Per-subblock ops performed by the wide decode (`Wide32Q8`, `native_mmvq.dp.cpp:1720-1733`),
one 32-quant block = two 16-quant halves (`LPB = 2`):

* **Load**: for each half `l`, `load16_a2(b->qs + 16*l)` pulls 16 quants as a raw `sycl::int4`
  (`:1725-1727`); no unpack.
* **Dot**: `dp4a4(r.q, ld_q8_16(xb, r.half), 0)` — one dot-product-of-four-int8 accumulate of
  the weight half against the Q8_1 activation half (`:1730`).
* **Scale**: `r.d * xb->ds[0]` — block weight scale times the fp32 activation `d`
  (`:1730`), then multiplied by the dp4a result.
* **Sum**: the `sumi`/dot accumulates across halves (narrow path `small_q8_dot`,
  `:807-816`, `sumi = STRATA_DP4A(v, u, sumi)`), then the block result is
  `d0 * d1 * sumi`.

No bit-gather, no codebook lookup, no per-16 unpack: every operator already runs on raw
signed bytes.

## 4. Verdict

**No pre-unpack is needed. Q8_0 is already at the byte ceiling.**

The `Q80Block` payload is already raw `int8` signed bytes (`native_mmvq.dp.cpp:104-106`), the
native decode already runs load+dp4a with zero bit-unpacking (`small_q8_dot` `:807-816`;
`Wide32Q8` `:1720-1733`; dispatched at `:2719-2722`), and the Q8_0 Wide32 path is exactly the
target that Q6_K's pre-unpack was designed to reach (`:2501-2502`). Pre-unpacking Q8_0 would
produce a signed-byte block no cheaper to decode than the one already stored, adding a copy
pass and a second buffer for no gain. The single open piece — the llama.cpp wide-load/ESIMD
DMMV reorder — was measured as not-a-win on Q8_0 in exp 12. Nothing to unpack, nothing to
pre-unpack. Do not implement.
